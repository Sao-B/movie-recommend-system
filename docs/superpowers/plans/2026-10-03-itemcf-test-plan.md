# ItemCF 独立推荐测试计划

日期：2026-10-03。状态：计划已编写，尚未实现或执行。

**目标：** 在已核验的 2,000 用户切片上，判断 ItemCF 是否提供比人气基线更有效的个性化排序，并区分“相似度不可靠”“邻域覆盖不足”“排序没有增益”等失败原因。允许结果为负，不预设必须超过 MostPop。

**本轮边界：** 只做本计划第 1–12 节的探索性试验，完成报告即停止。第 13 节是后续确认实验的建议，不属于本轮执行范围。当前用户请求仅为编写计划，不启动训练或修改应用。

### 2.3 共同候选与纳入用户

令 `I_train` 为训练段出现过的全部物品，`Seen_u` 为用户训练段评过的全部物品（包括低分），`R_u` 为验证段评分 ≥4.0 的去重物品集合。

```text
C_u = I_train - Seen_u
评测用户 = {u : |R_u| > 0}
```

预期 `|I_train|=11,380`，评测用户 1,930，70 位无验证正例用户不参与排序均值。已有 2 位用户的所有正例都在候选外，仍须纳入并计零分。

- 不按物品评分人数筛候选，不采样负例，不利用验证正例缩小候选。
- 验证正例不在训练候选中，仍保留在 Recall 分母和 NDCG 的理想 DCG 中。
- 没有训练好评的用户，只要验证中有正例，就必须保留；不能为了 ItemCF 好看而剔除。
- 所有方法导出相同的有序用户 ID 清单、候选全集哈希、逐用户 seen/relevant 哈希。先比较这些标识，数量相同并不足以证明协议相同。

## 3. ItemCF 的唯一定义

### 3.1 本轮选择二值共同好评

选择**二值好评余弦 ItemCF**，目标是 Top-N 排序。阈值固定为 4.0，与验证正例一致，不扫描阈值。

\[
X_{ui}=\begin{cases}1,&(u,i)\in Train\ \text{且}\ r_{ui}\ge4\\0,&\text{其他}\end{cases}
\]

这里的 0 表示“不作为正向相似度证据”，不等于明确不喜欢。低于 4 分的训练评分不参与共现矩阵，但这些电影仍进入 `Seen_u`，不会推荐给已经评过它们的用户。

本轮不使用用户均值中心化或修正余弦，不把 4.0/4.5/5.0 再赋不同权重，也不加入负反馈惩罚。这样只检验一条定义清楚的路线；丢失细粒度评分和负反馈是其限制，应写入结论。

### 3.2 支持度与相似度

分别保存两种支持度，禁止混用：

- `n_all(i)`：训练段所有评分人数，用于 MostPop、推荐流行度及支持度分层。
- `n_like(i)=sum_u X_ui`：训练段好评人数，用于相似度归一化和 LikePop。
- `c_ij=sum_u X_ui X_uj`：同时好评 i、j 的用户数，用于共现收缩。

\[
cos(i,j)=\frac{c_{ij}}{\sqrt{n_{like}(i)n_{like}(j)}}
\]

\[
s_{ij}^{(\beta)}=\frac{c_{ij}}{c_{ij}+\beta}\,cos(i,j),\qquad i\ne j
\]

规则：

1. 对角线设为 0；无共同好评、任一好评人数为 0 时，相似度为 0。
2. β=0 且 `c_ij>0` 时收缩系数为 1；`c_ij=0` 直接返回 0，避免 0/0。
3. β 是待验证的可靠性超参数，没有“理论保证能治冷门”的宣称，也不是候选门槛。
4. 非有限、负相似度或大于 `1+1e-12` 的相似度视为实现异常，停止排查，不静默裁剪。

### 3.3 邻居方向与打分

对每个**来源电影 j**，按 `(-s_ji, target_movie_id)` 保留最多 k 个正相似邻居，记为 `N_k(j)`。这是“从用户喜欢的电影向外找邻居”的定义。

原始相似度对称，但逐行截断后的邻居图通常不对称；不自动取双向并集，不强制互为邻居。

令 `H_u={j : 用户 u 在训练段给 j 的评分≥4}`，打分为：

\[
score(u,i)=\sum_{j\in H_u}s_{ji}\,\mathbf1[i\in N_k(j)],\qquad i\in C_u
\]

不除以相似度和，不加流行度项或偏差项，不归一化成 1–5 分。**该值是排序分数，不是预测评分**，因此 ItemCF 的 RMSE、评分越界率均记 N/A。

`E_u={i∈C_u : score(u,i)>0}` 为有邻域证据的候选。按 `(-score, movieId)` 从 `E_u` 取前 20。

**无证据处理：** `|E_u|<20` 时返回不足 20 条；`H_u` 为空或 `E_u` 为空时返回空列表。零分电影不按 ID 填满，热门电影也不暗中补齐。候选资格仍是共同的 `C_u`；ItemCF 的短列表是算法覆盖不足的结果，不改变相关集合或指标分母。

每条推荐须能分解为来源 j 的贡献 `s_ji`，并记录 `c_ji`、`n_like(j)`、`n_like(i)`。正式结果至少保存贡献总和、证据邻居数、最大贡献来源及其共现人数；固定案例保存全部贡献。

多个来源贡献相同时，最大贡献来源取 movieId 最小者。浮点贡献按来源 movieId 升序累加，避免遍历无序集合改变最后几位并影响并列排序。

## 4. 对照组与有限参数预算

### 4.1 实验组

| 名称 | 定义 | 次数 / 角色 |
|---|---|---|
| MostPop | `n_all(i)` 降序，平票 movieId 升序，排除 seen | 新跑 1 次，并与旧结果逐用户核对 |
| LikePop | `n_like(i)` 降序，平票 movieId 升序，排除 seen；不足正好评物品时按相同规则继续零计数物品 | 新跑 1 次，隔离“选择好评而不是所有评分”的影响 |
| BiasOnly | 仅 μ+b_u+b_i，λ=0.1，10 轮，按观测数正则 | 新跑 1 次，仅作病因诊断 |
| ALS-ref | rank=50、λ=0.1、10 轮 | 复用本次网格已核验的逐用户产物 |
| ALS-best-ranking | rank=50、λ=0.01、10 轮 | 同上；注明是在相同验证集选择的最佳 ALS，非盲测 |
| ItemCF | k∈{20,50,100} × β∈{0,10,50} | 9 个配置，全部报告 |
| ItemCF-repeat | 选定配置在相同训练数据上独立重建并评分 | 1 次，可复现性验证，不新增超参 |
| ItemCF-history-shuffle | 固定选定邻居图，使用错配训练历史评分 | 1 次诊断，不参与选参 |

没有 Random 新扫描或 ALS 重调参。既有 Random 分数来自另一轮两段协议，不能贴到本轮主表中。

### 4.2 ALS 产物复用条件

来源为 `experiments/pilot/out/grid/20261003T125319Z/`。使用 `rank50_reg0.1/`、`rank50_reg0.01/` 的 `summary.json`、`per_user.csv`、`top_recommendations.csv` 等原始产物，不能只抄报告中的四舍五入数字。

输入、切分、逐用户 seen/relevant、候选、用户顺序、Top-N 和并列规则全部核对后，重新计算主表指标。MostPop 应复现：NDCG@20≈0.07976736506824102，Recall@20≈0.10663327838454675，容差 `1e-10`。

任何一项不一致先停止比较，找出是新代码还是旧记录的问题；不能静默换基准。旧 ALS 耗时只标为历史运行成本，不能与当前缓存状态不同的新模型作严格速度竞赛。

### 4.3 BiasOnly 的定义与解释边界

固定 μ 为训练均分，初始 b_u=b_i=0，循环 10 次：先更新全部用户偏置，再更新全部物品偏置。

\[
b_u=\frac{\sum_{i\in I_u}(r_{ui}-\mu-b_i)}{n_u(1+\lambda)},\qquad
b_i=\frac{\sum_{u\in U_i}(r_{ui}-\mu-b_u)}{n_i(1+\lambda)}
\]

目标为 `SSE + λ[sum_u n_u*b_u² + sum_i n_i*b_i²]`，每轮记录目标及训练 RMSE，沿用网格的有限性、单调容差检查。可复用 `als.solve_bias`，但不通过修改旧 `fit_spark` 的 rank 下界来接入。

对固定用户，μ+b_u 不改变电影间顺序，因此 BiasOnly 等价于按 b_i 排序再排除 seen。这应成为一条测试。它若同样推低支持度电影，只能说明**偏置本身足以产生这种现象**，不能量化其对完整 ALS 的贡献，也不能证明隐因子没有问题。

## 5. 实现与计算规模

### 5.1 分块稀疏计算

- 输入由 Spark 从 HDFS 读取；本轮允许收集这份已固定的 304,944 条切片，和上轮规模相同。
- 在 Python driver 中用 SciPy 稀疏矩阵自研计算相似度，不调用现成推荐模型。明确记录：**Spark 负责输入读取，ItemCF 相似度在单机 driver 分块计算，不称为分布式训练**。
- X 使用有足够范围的整数类型（建议 int64）计数，禁止 uint8/bool 直接矩阵乘导致溢出或布尔化。
- 物品索引覆盖全部 `I_train`，包括没有好评的物品；userId/movieId 到矩阵索引的映射按数值排序保存。
- 默认块大小 128，逐块计算 `X[:, block].T @ X`。只保留稀疏结果，不构造全物品×全物品的稠密矩阵。
- **先对块内全部非零共现计算指定 β 下的相似度，再按该 β 取 top-k。** 禁止先取原始余弦 top-100 再收缩，因为收缩会改变邻居顺序。
- 为 β=0/10/50 各保存最多 100 个邻居；k=20/50 从该 β 的有序图取前缀。共用一次共现计算、三张图、九次评分，逐配置报告结果与缓存命中。
- 主评分只累加用户好评来源的已存邻居，之后排除全部 seen；不依靠验证正例建立候选。

共享预处理成本、三张图各自构建成本、九次评分成本分别计时；总耗时不把共享成本重复累计，也不能把缓存复用后的耗时冒称从零建模时间。

主 grid 内各阶段串行执行，最多同时有一个 Spark 计算进程。三张图及九次评分可以在一个受监控的工作进程中完成，每个阶段仍有独立状态和耗时。repeat、shuffle 必须另启进程；repeat 不可复用邻居图。

### 5.2 环境与运行限制

VM 参考环境：Python 3.6.8、NumPy 1.19.5、Spark 3.5.1、Java 8、2 CPU、约 4 GB RAM + 4 GB swap。执行前实测版本、空闲资源、SciPy 是否可导入和实际版本；不能只凭开发机安装情况判断 VM 可用。

保持 Python 3.6 兼容；BLAS/OMP/MKL 使用单线程。SciPy 缺失时先记录依赖问题，制定兼容安装方案，不自动升级系统 Python 或修改应用环境。

合成冒烟和真实数据首块探测通过后才构建完整图。若块计算内存不足，可把块大小从 128 降到 64 一次，先通过分块一致性测试，并在 manifest 中记录；这属于计算实现参数，不依据验证效果选择。仍失败则记录资源阻塞，不缩减候选或抽掉活跃用户来让实验“成功”。

每个独立运行任务（主 grid、repeat 或 shuffle）默认超时 30 分钟，由外层监督进程计时。超时留下状态、日志与已完成产物，未执行阶段标为 blocked，不自动延长。只终止本轮启动并记录的子进程，不按 Java/Python 进程名批量停止系统服务。

## 6. 指标：同时回答准确率、覆盖与证据问题

### 6.1 主指标和固定分母

- 主指标 NDCG@20，次指标 Recall@20；另报 K=5/10 的同口径结果，使用同一份 Top-20 前缀，不额外调参。
- 二元相关性；Recall 分母为 `|R_u|`，NDCG 的 IDCG 按 `min(K,|R_u|)` 计算。
- 短列表中没有返回的位置贡献 0；不能按实际返回长度重算 IDCG。空 ItemCF 推荐对已纳入用户贡献 Recall=0、NDCG=0。
- 先对共同的 1,930 用户逐人计算，再求均值；不得只对有邻居或有命中的用户求平均。

只有 BiasOnly 和既有 ALS 报评分预测 RMSE、原始预测越界率，沿用上轮训练内物品的 46,214 条验证评分及 `<0.5` / `>5.0` 边界，另列其推荐位置上的越界率。ItemCF、MostPop、LikePop 的这些字段为 N/A。评分误差仅为诊断，不进入 ItemCF 参数选择。

### 6.2 覆盖与诊断指标

| 指标 | 精确定义 / 用途 |
|---|---|
| 候选正例覆盖率 | `mean_u |R_u∩C_u|/|R_u|`，应与上轮约 0.9859616652 一致 |
| 证据正例覆盖率 | `mean_u |R_u∩E_u|/|R_u|`，只描述 ItemCF 能找到多少正例证据 |
| 证据集 Recall@20 上限 | `mean_u min(20, |R_u∩E_u|)/|R_u|`；最终 Recall@20 不得超过它 |
| 证据候选数 | 每用户 `|E_u|` 的 p10/p50/p90，以及为 0 的用户数 |
| 满额率 / 空列表率 | 返回 20 条 / 返回 0 条的用户数，分母都为共同评测用户数 |
| 填充率 | 实际推荐总条数 / `(20×评测用户数)` |
| Catalog Coverage | 推荐物品去重数 / `|I_train|`，保持所有模型相同分母 |
| 推荐流行度 | 实际推荐位置的 `n_all(i)` 均值、中位数、p90；保留跨用户重复推荐 |
| 低支持度比例 | 实际推荐位置中 `n_all(i)≤4` 的比例，同时给分母；零推荐记 N/A |
| 邻域证据强度 | 推荐电影的证据邻居数分布，以及最大贡献边的 `c_ji` 分布 |
| 不喜欢的已观察留出项命中 | Top-20 中验证评分≤2 的条目数 / 实际推荐数；未知评分不算差评，同时报告验证低分条数。仅诊断，不调参 |
| 列表个性化程度 | 与该用户 MostPop Top-20 的 Jaccard 重合度；更低不自动等于更好 |

主表同时展示推荐条数、满额率、覆盖率和支持度，避免用短列表换来表面较低的冷门比例。另可展示“有训练好评”用户子表，但它不能替代全体主结果。

### 6.3 口味与分层，仅作诊断

元数据只参与结果解释，不进入相似度、打分或候选筛选。

- 口味吻合度：训练好评历史与推荐列表的 genre 分布余弦相似度；每部多类型电影权重均分。忽略 `(no genres listed)`；历史无有效 genre 的用户为 N/A，固定同一批具有历史 genre 的评测用户。历史有效但推荐为空/推荐无有效 genre 时记 0，同时报告缺元数据比例。指标高不能代替 NDCG 增益。
- 按训练好评条数分层：0、1–5、6–20、>20；逐层报告人数、NDCG、Recall、满额率。
- 按训练 `n_all(i)` 固定分箱：候选外、1–4、5–19、20–99、≥100；报告各箱验证正例数和被 Top-20 命中的比例。称“分箱正例召回”，不与全体 NDCG 混称。
- 不按验证成绩挑用户。案例在跑模型前固定：从上述非空用户层各选最小 userId 的 2 人；无该层就报告为空。保留失败案例。

元数据无法取得或指纹无法确认时，genre 指标、电影标题和相关图注标为 N/A，并说明原因；ID、支持度、邻域证据和主排名指标仍可完成。不得为补元数据改动生产数据库或调用外部富化服务。

### 6.4 配对区间与参数选择

对每个配置和对照，保存逐用户 NDCG/Recall。对相同用户的差值做 paired bootstrap：seed=42，2,000 次有放回抽样，报告均值差和 percentile 95% 区间。两模型每次抽取相同用户索引，不把所有推荐位置当独立样本。

参数选择固定为：NDCG@20 降序；差异绝对值≤`1e-12` 视为平手，再依次比较 Recall@20、较小 k、较小 β。不得依据口味图、某个案例或其他 K 临时改主指标。

所有 9 个配置公开，不只展示最佳项。由于是在同一验证集上选最佳，区间只是这批用户上的探索性不确定性描述，**不把最佳项区间排除 0 当作已经完成独立显著性验证**，不宣称对未来用户必然有增益。

## 7. 正确性测试清单

先写独立期望值的测试，再实现。不能仅用同一实现跑两遍互相证明正确。

### 7.1 手算金标准

给 3 位用户的训练好评集合：`u1={A,B}`、`u2={A,C}`、`u3={A,B,C}`。

```text
n_like(A)=3, n_like(B)=2, n_like(C)=2
c_AB=2, c_AC=2, c_BC=1
cos(A,B)=cos(A,C)=2/sqrt(6)
cos(B,C)=1/2
β=10: s_AB=(2/12)*(2/sqrt(6)); s_BC=(1/11)*(1/2)
```

测试评分表还应包含一条低分记录、一个零好评物品和非连续 movieId，验证低分不参与相似度、但必须被 seen 排除。独立验证分数累加、并列顺序与映射，不只验证矩阵形状。

### 7.2 必须覆盖的测试

| 类别 | 验证内容 |
|---|---|
| 数据防泄漏 | 改变验证/测试评分不得改变模型图；测试分数变化不影响本轮指标；切分 ID/条数/哈希与旧协议一致 |
| 共现计数 | 手算金标准、仅训练数据、重复 `(u,i)` 拒绝；260 个共同好评用户不会因 uint8 溢出 |
| 相似度边界 | 自相似剔除、无共同好评为 0、零好评列为 0、β=0、有限性和取值范围 |
| 截断顺序 | 构造例子验证“先收缩再 top-k”；不能复用 β=0 的邻居集合替代其他 β |
| 邻居方向 | 构造非互惠 top-k 图，验证来源 j→目标 i 的累加，避免误用图的转置 |
| k 和并列 | 正邻居不足 k；正分并列按 movieId 升序；k 前缀与独立计算一致 |
| 分块对拍 | 小矩阵稠密暴力结果 vs 稀疏结果；块大小 1/2/128、输入行序打乱后结果一致 |
| 用户打分 | 多个来源贡献求和；训练低分电影不推荐；无好评/孤立来源/空候选返回空 |
| 排序指标 | 候选外正例、无证据正例保留分母；短列表和空列表；Recall 不超过证据上限；禁止重复推荐 |
| 证据解释 | 推荐分数等于所保存贡献总和，容差 `1e-10`；解释电影都在该用户训练好评历史中 |
| 基线与诊断 | LikePop 用好评人数而非均分；BiasOnly 手算闭式解、目标单调、按 b_i 排序等价 |
| 统计 | 配对 bootstrap 同索引；完全相同列表的差值区间为 [0,0]；固定 seed 可复现 |
| 序列化 | 稀疏邻居图保存/读取结果一致；输入/配置/索引哈希不符时拒绝复用缓存 |
| 运行失败 | 子进程失败、超时、损坏 JSON、运行中源代码变化均有状态；公共协议错误阻断后续比较 |

再做完整合成管线：输入 → 切分 → 9 配置 → 原始明细 → 汇总 → 独立重算，成功后才读取真实切片。单测通过不等于已排除所有模型或协议问题。

## 8. 可复现性和历史错配诊断

选定配置单独启动新进程、从训练评分重新构图并评分，不读取第一次的图缓存。要求邻居 ID/排序、推荐 ID/排序、用户列表完全一致；所有浮点分数与指标绝对差≤`1e-9`。环境、输入、代码和配置相同才可作此比较。

错配诊断只跑选定配置一次：固定邻居图、目标用户的 `C_u` 与验证 `R_u`；用 seed=42 将全部训练用户排成随机序列，并循环移动一位，给每位目标用户分配另一个人的好评历史。保存 donor 映射，确保不分配本人；每个历史恰好使用一次。

重新按该错配历史打分，但仍排除目标用户本人的全部训练已评电影。所有目标评测用户保留。比较真实历史与错配历史的配对指标差。

该诊断保留总体历史分布，但会改变单个用户的历史长度，且邻居图仍含目标用户的训练数据。因此它只能提供“分配正确历史是否有帮助”的辅助证据；不能要求错配后必须掉到 Random，也不能单独证明模型学到了偏好。错配后无下降时如实报告，不重新选 seed。

## 12. 验收与结论分级

**工程验收：** 测试和真实环境冒烟通过；所有预定配置/基线有终态（含明确失败/阻塞），成功项原始记录完整；公共正确性问题全部解决后才解释模型优劣；最佳配置重建一致；指标和证据可独立重算。若图无法构建或复跑不一致，结论是工程未完成，不能据失败指标否定算法。

**效果判断：**

1. **超过 ALS，但未超过 MostPop/LikePop：** 证明本切片上这条路线优于已有 ALS，尚无总体排序收益证据。案例或口味指标好看不能改写主结论。
2. **NDCG 与 Recall 均超过两个人气基线：** 值得进入独立数据确认；报告绝对差、配对区间、短列表/资源代价，不能直接宣布适合上线。
3. **NDCG 与 Recall 方向相反：** 明确写为权衡，不概括为“全面提升”；仍按预定 NDCG 主指标选参，但保留 Recall 退步。
4. **证据上限低：** 当前邻域/历史/数据下找不到足够正例，排序器即使完美也受限；不能通过删掉无证据用户提高均值。
5. **上限尚可、实际 Recall 低：** 有证据候选的排序值得排查；不据此单独认定评分公式是唯一原因。
6. **收缩无收益、β=0 最好：** 如实接受，不能预设共现收缩一定有效；最佳参数落在边界也只记录，不自动扩大扫描。
7. **全部失败或人气基线仍明显占优：** 本轮停止。下一步需重新评估数据、任务目标与方案，不立即堆叠融合来掩盖结果。

## 13. 后续独立确认建议（不在本轮执行）

本轮不能解决“全量是否更好”或“最终能否泛化”这两个问题。若 ItemCF 值得继续，先冻结公式、参数、对照和指标，再制定独立确认实验：

- 使用尚未参与本次路线选择的新评测用户/留出段，核对已有 2k、20k 和历史审计的数据使用记录；无法证明未使用时，不能称为盲测。仅换随机种子不足以保证独立。
- 若要检验样本量效应，固定评测用户、相关集合、候选与时间规则，只增加其他用户的训练数据；所有模型在每个规模上重新计算训练统计。不能复用不匹配的新旧指标来推断学习曲线。
- 若要模拟真实上线，采用共同的全局时间截点；相似度、偏置、人气、元数据可用性都只取截点以前，再评估以后数据。它与当前每用户时序协议分别报告。
- ItemCF 和两个人气基线使用同一协议；若比较 ALS，也必须在新协议上重训，不能直接拿当前验证集最佳数字对比。

这一步的用户清单、时间截点和计算规模应另行形成执行计划，本轮不预支未经验证的全量资源预算。
