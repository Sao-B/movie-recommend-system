## 3. 冻结数据与评估协议

### 用户选择

1. 从旧 2k、20k 切片中读取全部 userId，取并集作为最低排除名单；不是只排除有正例的评测用户。核对已有评测记录，有额外明确用于推荐评估的用户清单时一并排除，注明来源。
2. 从完整数据的剩余用户中，按 `(sha256("itemcf-confirm-cohort-v1:" + str(userId)), userId)` 升序取前 **20,000 人**；保留其全部评分。userId 为原始正整数，以无前导零十进制字符串参与哈希。
3. 在这 20,000 人中，按另一独立顺序 `(sha256("itemcf-confirm-eval-v1:" + str(userId)), userId)` 取前 **2,000 人作为固定评测名单**。名单在看留出评分和指标之前落盘，不按活跃度、好评数或结果筛人。
4. 输出旧用户排除名单、新 cohort、评测名单以及 SHA-256，断言新旧用户交集为空、评测名单是 cohort 子集。
5. 旧 20k 切片缺失时，应从原始输入和已验证的旧抽样实现重建并核对历史行数 3,135,106；核对不上则停止数据准备，不能假设换 seed 就独立。

**独立性的准确表述：**“排除了已识别的历史实验用户的新用户群体确认”。完整 MovieLens 曾用于生产 ALS 训练，因此不声称这些评分从未被任何历史模型读取；无法穷尽旧评测名单时明确披露，不称严格盲测。

### 切分与方法

| 项目 | 本轮固定规则 |
|---|---|
| 切分 | 每用户按 `(timestamp, movieId, 原始行序)` 排序，前约 80% 训练、最后约 20% 测试；复用 `experiments/pilot/data.py::temporal_split` 的取整规则 |
| 为什么两段 | 参数已经冻结，无须再留验证段。与旧 64/16/20 探索协议不同，旧新绝对指标不能据此推断数据规模效应 |
| 训练数据 | 20,000 人各自的训练段；非评测用户的留出段同样不进入统计或邻居图 |
| 评测数据 | 预先固定的 2,000 人的测试段；只剔除测试段没有 ≥4 分正例的用户，并报告人数；不补抽用户 |
| ItemCF | 训练评分 ≥4 二值化；余弦相似度；`beta=0`，每个来源电影最多 100 个邻居；累加用户训练好评电影的邻居贡献 |
| 邻居与推荐平票 | 邻居按 `(-similarity, target_movieId)`；推荐按 `(-score, movieId)`；浮点贡献按来源 movieId 升序累加 |
| MostPop / LikePop | 分别按全部训练段的评分人数 / ≥4 分人数降序；平票 movieId 升序 |
| 候选 | 训练段出现过的全部电影，排除目标用户训练段所有已评分电影，包括低分电影 |
| 推荐长度 | Top-20；ItemCF 无正贡献不返回，不用热门或零分填满 |
| 正例与分母 | 测试 ≥4 分电影；候选外正例保留在 Recall 和 IDCG 分母中；无证据用户计零，不剔除 |

这仍是每用户时序协议，可能使用其他用户在更晚日历时间的训练行为；同秒评分可跨边界。它不是共同全局时间截点回测，也不声称模拟了真实上线时间线。

## 5. 指标、产物与判定

**主表仅三行：** ItemCF、MostPop、LikePop；列为 NDCG@20、Recall@20、有效用户数、满额率、电影目录覆盖率、训练/评分耗时和峰值 RSS。ItemCF 不是评分预测模型，不计算 RMSE。

对固定用户做配对 bootstrap：seed=42、2,000 次、95% percentile 区间，报告 ItemCF 相对两个基线的绝对差和相对差。区间解释为这个固定训练图下的用户层面不确定性，不代表重训或跨时间的全部不确定性。

落盘位置：VM `/home/h/itemcf_confirmation/<run_id>/`，本地 `experiments/itemcf/out/confirmation/<run_id>/`。保留：

- `manifest.json`、`source_hashes.json`、三份用户名单、训练/测试计数；
- 邻居数组、`per_user.csv`、`recommendations.csv`、`summary_table.csv`、`bootstrap.json`；
- 日志、`resources.csv`、`run_status.json`、`verification.json`；
- `conclusion.md`：三行主表、一张对比图（可选）、差值区间、限制与下一步判断。图不作为运行成功的条件。

判定规则预先固定：

1. NDCG、Recall 都超过两个人气基线，且对较强基线的 NDCG 差值区间下界 >0：支持进入系统接入与全量资源评估；仍不宣称全量已经验证。
2. 均值提升但区间跨零，或两个指标方向不一致：如实写为证据不足或存在权衡，不追加调参直到获胜。
3. 未超过基线：报告未复现优势并停止，保留热门推荐作为可靠对照。
4. 资源/正确性失败：报告工程未完成，不把失败记为算法效果零分。

论文分开呈现“旧切片模型选择”和“新用户群体确认”。这一轮改变了人群、规模和训练/留出比例，不是固定评测集的学习曲线；不要说指标变化必然由训练数据增多造成。
