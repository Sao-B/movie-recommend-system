## 1.1 分子与分母必须同口径（本轮最贵的一课）

相似度是 `c_ij / sqrt(n_like(i) · n_like(j))`。**分子与分母必须来自同一人群、
同一侧（训练段）**，否则相似度被系统性缩放。本轮实际踩了两次：

| 错误 | 现象 | 怎么发现 |
|---|---|---|
| 分子只用 2,000 评测用户的共现，分母用全库 `n_like` | ItemCF 的 NDCG/Recall **双双 0.0**，覆盖率只剩 202 部 | 全量跑通后看指标是否合理 |
| 分子用训练段（25.7M 行），分母用全量 32M 行 | 相似度差 1.1~1.5 倍（倍率不固定） | **独立核验器的抽样对拍** |

第二条**只看指标抓不到**——Top-20 的排序对全体用户的共同缩放因子不敏感。
只有"从原始评分独立重算相似度"才能发现。这就是本轮必须做独立核验的理由。

## 3. 候选与推荐

| 项 | 冻结值 |
|---|---|
| 候选集 `C_u` | 图上出现过的全部物品（= 训练段出现过的全部 movieId）减去 `Seen_u`（训练段评分过的全部电影，**含低分**） |
| 推荐长度 | Top-20 |
| ItemCF 空列表 | **不补齐**：无正贡献即不返回该条目 |
| ItemCF 分数 | `score(u,i) = Σ_{j ∈ H_u} c_ij · 1[i ∈ N_k(j)]`，`H_u` = 训练段 `>= 4.0` 的电影，`N_k(j)` = 按 `(-s_ji, i)` 取前 100（**排除 j 自身**） |
| 相似度 | `s_ji = c_ji / sqrt(n_like(j) · n_like(i))`，`beta=0` ⇒ 无收缩 |
| MostPop / LikePop | 全库按 `n_all` / `n_like` 降序（平票 movieId 升序），排除 `Seen_u` 后取前 20；**总是满额** |
| 排序决胜 | ItemCF 按 `(-score, movieId)`；贡献按来源 movieId 升序累加 |

## 4. 指标

- `Recall@20(u) = |Top20(u) ∩ R_u| / |R_u|`，`R_u` = 测试段 `>= 4.0` 的电影集合。
- `NDCG@20(u)`：`DCG = Σ 1/log2(rank+1)`（命中项），`IDCG = Σ_{p<min(|R_u|,20)} 1/log2(p+2)`。
- **候选外正例保留在分子与分母里**：`R_u \ C_u` 的条目永远不会被返回，但它计入 `|R_u|` 与 IDCG。
  本轮该情形**必然出现**（协议 A 下评测用户里约 2 人训练段为空），这是既有口径第一次被真正检验。
- **分数 = 0 的候选不返回**：`|R_u| <= 20` 时模型本可返回满 20 条，但分数为 0 的条目不返回，
  因此**并非所有正例都有机会被排出**。这条对两个"总是满额"的人气基线略微有利，本轮不改口径。
- 有效用户数、满额率、空列表率、目录覆盖率（命中物品集合 / 候选物品数）一并报告。
- 差值：对固定用户做配对 bootstrap（`seed=42`、2000 次、95% percentile），
  报绝对差、相对差、区间、是否排除 0。区间只表示**固定训练图下用户层面的不确定性**。

## 5. 判定规则（预先固定）

| # | 条件 | 判定 |
|---|---|---|
| 1 | NDCG 与 Recall 均超过两个基线，且对较强基线的 NDCG 区间下界 > 0 | **优势在全量规模下成立**，支持进入系统接入与 genres 冷启动 |
| 2 | 均值提升但区间跨零，或两指标方向不一致 | **证据不足/存在权衡**，如实写，不追加调参 |
| 3 | 未超过基线 | **优势不成立**，如实报告，不调参直到获胜 |
| 4 | 资源或正确性失败 | **工程未完成**，不把失败记为算法效果零分 |

较强基线按 NDCG@20 现场判定（MostPop 与 LikePop 在不同规模下谁更强并不稳定）。

## 6. 资源与监督（沿用已修好的口径）

- 独立进程监督（`rate_limited_guard`），采样间隔 2 s，worker 被阻塞时仍能被采样。
- 终止线：进程树 RSS > **3 GiB**；`MemAvailable` 连续 30 s < **256 MB**；磁盘 < 2 GiB；总量预算 8 小时。
- **墙钟预算按块刷新**：构图按列块推进，每块结束显式刷新监督 deadline，
  因此"总预算"是真正的 8 小时上限，**不是** 4~7 分钟的单块墙钟误杀。
- BLAS 线程设 1；任何时刻只允许一个计算进程。
