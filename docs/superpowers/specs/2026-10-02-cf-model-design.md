## 0. 背景与设计铁律

现网模型（MLlib ALS + 在线 fold-in）的问题不是某个参数错，而是**设计不完善导致补丁越打越乱**。
本文档把历史补丁背后的真实病因逐个钉死，在设计期给出结构性归宿：

| 历史现象 | 真实病因 | 设计期归宿 |
|---|---|---|
| 预测分截断（裸分冲到 8，全被 clamp 成 5.0） | 预测式是裸点积，未锚定 1~5 分尺度 | 预测式恒含偏差项 μ + b_u + b_i（§3.1），验收判据见 §6.4 |
| 小众冷片霸榜（点 20 条好评后全推小众电影） | 低支持度物品的 rank 维因子欠定，点积虚高 | 支持度收缩项 n_i/(n_i+τ)，τ=rank 为推导量纲（§3.1）；旧候选门槛降级为消融对照臂（§6.3） |
| λ 口径两侧不一致 | 训练/求解各自定义目标函数 | 目标函数唯一定义 `objective.py`，训练与求解共用（§3.1、§5.4） |
| 推荐连用户口味标签都不符 | 推荐目标中没有口味对齐信号，且无指标度量 | ItemCF 邻域证据进级联精排（§4）；「口味吻合度」指标 + 案例图（§6.2） |

**三条铁律**（杜绝补丁复发）：

1. **数学定义先于代码**：预测式、目标函数、正则项先显式写出，训练器与在线求解器共用同一份定义；
2. **不调用任何现成模型实现**（MLlib ALS、Surprise 等一律不用）；
3. **每个组件可独立验证**：合成小数据上与闭式解/暴力解对拍，通过后才上 32M 全量。

## 2. 阶段 0：数据与实验协议（一切模型的地基）

### 2.1 数据

- **MovieLens-32M**：`ratings.csv`（32,000,204 条评分）+ `movies.csv`（genres 列供口味吻合度计算）；
  用户约 20 万、有评分电影约 8.4 万（以数据剖析脚本实测为准，不硬编码）。
- **存储**：上传 HDFS `/movielens/`（`scripts/init_hdfs.sh`）；训练数据、切分结果、模型产物、评估结果**全部走 HDFS 路径**，不落本地盘。
- **数据剖析**（Spark 脚本，P1 之前跑）：用户/物品评分分布、长尾曲线、评分时间跨度 → 输出统计表，作为论文素材与超参决策依据。

### 2.2 切分协议

| 层 | 规则 |
|---|---|
| **主切分（定案）** | 每用户按 `timestamp` 升序，**留最后 20%（最少 1 条）为测试集**，其余进训练段 |
| 验证集 | 从训练段末尾再留 10%（每用户时序），**只用于选超参** |
| 测试集纪律 | 全程只碰一次；任何超参、权重、阈值不得依据测试集表现调整 |
| 候选集 | **全量物品**（训练集出现过即可），不设人为门槛 |

选「留最后 20%」而非 leave-one-out 的理由：每用户多个测试项时 Recall@K/NDCG@K 才是真正的排序质量度量（LOO 下退化为命中率）；能测「粗排 Recall@K 上限」（§4 级联必须量化的量）；稀疏用户自动退化为留 1 条，等于免费附赠 LOO 行为。

### 2.3 指标体系

| 类别 | 指标 | 说明 |
|---|---|---|
| 评分预测 | RMSE、MAE | 测试条目上计算 |
| 排序质量 | Recall@K、NDCG@K、MRR（K=5/10/20） | 主指标 NDCG@20 与 Recall@20 |
| 系统侧 | Coverage、Novelty（推荐物品平均评分人数） | 与准确率的权衡 |
| **口味吻合度** | Top-20 的 genre 分布 vs 用户历史 genre 分布的余弦相似度，按用户平均 | 度量"推的电影符不符合口味"；多类型电影按均分权重计入 |

**统计口径**：所有模型使用同一切分、同一用户样本；模型间差异报 paired bootstrap 95% CI。

## 3. 模型设计（P1 选模型）

### 3.1 统一预测式与目标函数（唯一事实来源 `objective.py`）

$$\hat r_{ui} = \mu + b_u + b_i + \underbrace{\frac{n_i}{n_i + \tau}}_{\text{支持度收缩}}\ \mathbf p_u^\top \mathbf q_i, \qquad \tau = rank$$

$$\min \sum_{(u,i)\in\Omega}\big(r_{ui} - \hat r_{ui}\big)^2 + \lambda\Big(\sum_u n_u\|\mathbf p_u\|^2 + \sum_i n_i\|\mathbf q_i\|^2 + \sum_u n_u b_u^2 + \sum_i n_i b_i^2\Big)$$

设计要点：

- **偏差锚**：μ≈3.5 起锚 + b_i 修正口碑，预测分结构上回到 1~5 尺度（治截断）；
- **支持度收缩**：观测数远小于参数量时隐因子贡献向 0 收缩（治小众虚高）。τ=rank 是推导量纲（观测数达到参数量时收缩减半），**不是调参**；与贝叶斯平均基线（§3.4 L2）共用同一公式；
- **正则按观测数缩放**（λ·n_u）：与目标函数定义写在同一处，训练/求解共用（治 λ 口径）。λ vs λ·n 口径作为消融项（§6.3）；
- **BisMF 是本式在 rank=0 的退化形态**，实现共享一套代码。

### 3.2 候选模型（全部自研实现）

| # | 模型 | 流派 | 定义 | 角色 |
|---|---|---|---|---|
| L0 | Random | — | 均匀随机 | 评测管线验错器（低于 Random = 实现有 bug） |
| L1 | MostPop | — | 按训练集评分人数降序 | 人气信号基线 |
| L2 | TopRated | — | 按贝叶斯平均分降序：$\frac{n_i}{n_i+m}\bar r_i + \frac{m}{n_i+m}\mu$，m=评分人数中位数 | 口碑信号基线 + 收缩消融锚点 |
| L3 | ItemCF | 基于邻域 | $\hat r_{ui}=\frac{\sum_{j\in N_k(i)\cap I_u} s_{ij} r_{uj}}{\sum_{j\in N_k(i)\cap I_u} |s_{ij}|}$，s 为修正余弦，k=50 | 邻域流派代表 + 级联精排器 |
| L4 | BiasMF | 基于模型 | §3.1 式取 rank=0 | 消融锚点（量化偏差项值多少分） |
| L5 | **MF-ALS** | 基于模型 | §3.1 式，分布式 ALS 交替闭式解 | **主推单路模型** |
| P | **ALS + ItemCF 级联** | 混合 | 见 §4 | **提案模型（最终交付）** |

**MF-ALS 训练法（交替最小二乘）**：固定物品因子解全体用户向量，再固定用户向量解全体物品因子，交替至收敛。每步闭式解：

$$(\mathbf Q_u^\top \mathbf Q_u + \lambda n_u \mathbf I)\,\mathbf p_u = \mathbf Q_u^\top(\mathbf r_u - \mu - \mathbf b_u - \mathbf b_i)$$

选择 ALS 而非 SGD 的理由：闭式解、确定性、无学习率等不确定性参数、每轮只广播/聚合 50×50 矩阵，弱集群可跑。

**选模型判据**：主看 NDCG@20 与 Recall@20，并列时依次看 RMSE、Coverage、Novelty、训练成本。

### 3.3 ItemCF 实现要点

- 相似度矩阵规模大（8 万×8 万），**分块稀疏矩阵乘**（按物品分块 ~1000，`scipy.sparse` 计算块×全量，逐块取 top-k）；
- 相似度与邻居表**只在训练集上计算**（防泄漏）；
- 参数 k=50（敏感性分析见 §6.3）。

### 3.4 已定案的取舍

- **不做** MF-SGD 变体、**不做** MLlib ALS 对照行；
- 基线三步（L0/L1/L2）全留：各隔离一个变量，训练成本为零；
- **UserCF、"先定标签再看标签下热度"两支思路移入 §9 范围外备选**：UserCF 现阶段引入会再造"邻居数/重合度"形式的门槛，时机不成熟。

## 4. 级联设计（提案模型 P）

```
Stage 1  ALS 粗排：MF-ALS 全量打分（偏差锚 + 支持度收缩）→ Top-K 候选（K=100）
Stage 2  ItemCF 精排：对候选做邻域打分 → 分数归一化 → 与 ALS 分加权融合 → Top-20
```

- **级联上限约束（必须量化）**：Stage 2 只能在 Stage 1 候选内排序，最终 Recall@20 ≤ 粗排 Recall@K。图 7 把「粗排上限 / 级联终值 / 两单路」随 K 变化画出；
- **融合的量纲纪律**：ALS 输出为点积（偏移量级）、ItemCF 输出为加权均分（1~5 量级），**不可直接相加**。候选集内 min-max 归一化后加权，权重 α 在验证集上定；同时报 RRF（名次融合，量纲不敏感）作交叉验证。**协议自检**：α=1 应回到纯 ALS 水平、α=0 回到纯 ItemCF 水平，对不上即实现 bug；
- **小众电影问题的双保险**：冷门且无邻域证据的电影，在收缩项（虚高被压）与邻域证据（无人背书）下自然降权——不设任何门槛开关；
- **口味标签（genres）不进打分公式**：只作为验证指标与案例图（§6.2），避免引入新参数与滑向内容过滤。

## 5. 阶段 2：分布式训练工程（Hadoop 技术栈）

### 5.1 拓扑

- **HDFS 是硬要求**：hadoop102 NameNode（前置步骤 `start-dfs.sh`；三节点现仅启 102）；
- Spark 计算：`spark-submit`，master 可切 `yarn` / `local[*]`，论文如实写部署形态；
- 产物布局：`/movielens/models/<run_id>/`（因子、邻居表、manifest、评估 CSV、图）。

### 5.2 代码布局（新建 `models/`，与现有生产 `spark/` 互不干扰）

```
models/
├── objective.py     # §3.1 预测式与目标函数的唯一定义（训练/求解共用）
├── data.py          # 读 HDFS、时序切分、候选集、数据剖析
├── mf_als.py        # 分布式 ALS（含 BiasMF 退化形态）
├── item_knn.py      # 分块相似度 + top-k 邻居
├── cascade.py       # 级联编排：粗排 → 归一化 → 融合 → 精排
├── solver.py        # 固定物品因子求用户向量（与训练同一目标函数）
├── metrics.py       # RMSE/MAE/Recall/NDCG/MRR/Coverage/Novelty/口味吻合度
├── plots.py         # matplotlib 出图（§6.2 清单）
└── manifest.py      # run manifest 生成与校验
tests/               # 用例见 §5.4
```

### 5.3 训练流程

HDFS 读取 → 时序切分 → 迭代训练（同步监控训练损失与验证集 RMSE 曲线）→ 因子/邻居表写 `/movielens/models/<run_id>/` → 评估出 CSV + 图。

### 5.4 可复现性与正确性护栏（TDD，先写测试再写模型）

**可复现（验收标准，非口号）**：

1. **run manifest**：git commit、配置快照、输入数据指纹（行数 + 评分和校验）、随机种子、Spark/Java/Python 版本、分区数、run_id；
2. **确定性执行**：显式 hash 分区、固定种子、ALS 闭式解无随机性；
3. **双跑一致性测试**：同配置跑两次，因子与全部指标逐位一致（浮点容差 ≤1e-9）。

**正确性护栏（单测清单）**：

- 合成 3×3 小矩阵上 ALS 单步 vs NumPy 直接解对拍；
- 收缩项边界：n_i→0 时预测退化为偏差预测、n_i→∞ 时收缩系数→1；
- 损失单调下降断言；
- 切分无泄漏断言（测试条目 timestamp 严格晚于该用户训练条目）；
- 归一化/融合协议自检（§4 的 α 端点回落）。

### 6.3 消融与敏感性清单

| 类型 | 项 | 取值 |
|---|---|---|
| 消融 | 偏差项 | on / off（L4 vs L5） |
| 消融 | 支持度收缩 | on / off |
| 消融 | 正则口径 | λ vs λ·n（历史事故直接变成论文消融点） |
| 消融 | 级联三件套 | ALS-only / ItemCF-only / 级联（融合权重 α 扫描 0→1） |
| 敏感性 | rank | 20 / 50 / 100 |
| 敏感性 | λ | 数量级扫描 |
| 敏感性 | ItemCF k | 20 / 50 / 100 |
| 敏感性 | 粗排 K | 50 / 100 / 200 |
| 敏感性 | 候选门槛对照臂 | 0 / 10 / 50 / 100（检验旧门槛方案 vs 收缩方案，替代当年的补丁） |

### 6.4 验收判据与证伪条件（预先声明）

**验收判据**：

- 预测分越界率（<1 或 >5）**< 0.1%**（图 11；旧式裸点积的越界率同图对照）；
- 双跑一致性逐位通过；
- 级联 NDCG@20 > max(两单路)；级联 Recall@20 ≤ 粗排 Recall@K（协议自检，超限即实现 bug）；
- 任何模型低于 Random → 先查实现，不许下结论；
- 收缩机制显著降低 Top-20 中低支持度物品占比（图 10 佐证）。

**证伪条件（必须如实报告）**：

- 若级联无增益（两路信号高度相关）→ 负面结论如实写，不挑 α/指标掩盖；
- 若收缩后小众霸榜依旧 → 病因判断有误，先复查评测协议（切分、候选、归一化、种子）再改模型；
- 实验结果与预期不符时，**先查协议，再下结论**。

## 9. 范围外（明确不做 / 备选）

- **UserCF 精排**（备选）：「找看过重合电影的用户」思路；现阶段引入会再造邻居数/重合度形式的门槛，留待后续；
- **「先定标签、再看标签下热度」**（备选）：genre 条件化的热度排序；滑向内容过滤，与协同过滤主题不符；
- **口味硬过滤**：砍惊喜度与覆盖率，不做；
- MF-SGD、MLlib ALS 对照、深度模型（NeuMF/LightGCN/SASRec）、显著性以外的统计检验、在线 A/B、论文写作。

## 10. 复现方式（实验全流程）

1. `init_hdfs.sh` 上传 ML-32M → HDFS `/movielens/`；
2. 数据剖析脚本产出统计表；
3. `models/` 按 §2.2 切分 → §3 训练各候选 → §4 级联；
4. 评估脚本出 §6 全部指标 CSV → `plots.py` 出图；
5. 每次运行落 run manifest；双跑一致性测试通过才算实验成立。
